# Growmore AI Assistant - Final Implementation Plan (OpenRouter-Based)

## 1. Objective
Build an AI-driven analytical reasoning layer that:
- Consumes existing Growmore outputs (not raw market data)
- Interprets why a strategy behaves as it does
- Explains risk, stability, and execution quality
- Never predicts prices or gives trading advice

The AI assistant operates only after:
- Backtest completion
- Strategy testing completion
- Paper trading simulation completion

The AI layer does not interfere with execution logic.

## 2. High-Level Architecture
```text
Backtest Engine
Paper Trading Engine
Strategy Testing Engine
        |
        v
MongoDB (Reports & Logs)
        |
        v
Context Builder (Python)
        |
        +-- FAISS (RAG: definitions & rules)
        |
        v
OpenRouter LLM (Analytical Model)
        |
        v
AI Insights API (FastAPI)
        |
        v
Frontend (Insights / Explanations)
```

## 3. Data Sources (Explicit Scope)
The assistant only uses data already generated by Growmore.

### A. Strategy Configuration
**Source:** `strategies` collection (MongoDB)

**Used fields:**
- Entry and exit logic
- Indicators used
- Timeframes
- Risk rules (if defined)
- Execution assumptions

### B. Backtest Result Report
**Source:** `backtests` collection

**Used fields:**
- Net PnL
- CAGR
- Sharpe, Calmar
- Max drawdown
- Drawdown duration
- Volatility
- Expectancy
- Profit factor
- Trade count
- Equity curve summary
- Win/loss distribution

**Purpose:** Explain historical performance structure and risk behavior.

### C. Strategy Testing Report
**Source:** `strategy_tests` collection

**Used fields:**
- Parameter variations (if any)
- Performance consistency
- Sensitivity indicators
- Stability across conditions

**Purpose:** Identify fragility vs robustness (without optimization).

### D. Paper Trading Simulation Report
**Source:** `paper_trades` / `paper_sessions`

**Used fields:**
- Live-simulated PnL
- Trade timestamps
- Loss clustering
- Overtrading patterns
- Execution drift vs backtest
- Session-level drawdowns

**Purpose:** Behavioral and execution realism analysis.

### E. Growmore Aggregate Results
**Source:** Aggregated summaries (MongoDB / Redis)

**Used fields:**
- Cross-report comparisons
- Backtest vs paper divergence
- Time-based summaries

**Purpose:** Forward-validation insight (not prediction).

## 5. Context Builder (Core Component)
**Responsibility:** Convert Growmore reports into LLM-ready analytical context.

### Responsibilities
- Fetch reports from MongoDB
- Summarize long trade logs
- Normalize metrics
- Remove noise
- Enforce deterministic context formatting

### Key Methods
- `build_strategy_context(strategy_id)`
- `build_backtest_context(backtest_id)`
- `build_strategy_test_context(test_id)`
- `build_paper_trade_context(session_id)`
- `build_execution_context()`

### Output
Structured JSON transformed to formatted analytical text with:
- Performance summary
- Risk summary
- Behavioral summary
- Execution assumptions

**Constraint:** LLM never queries MongoDB directly.

## 6. RAG Layer (FAISS)
**Purpose:** Supplement reasoning with definitions and platform rules, not live data.

### Indexed Content
- Metric definitions (Sharpe, expectancy, drawdown, etc.)
- Risk interpretation guidelines
- Growmore platform rules
- AI limitations text

### Not Indexed
- Market data
- Strategy results
- Trade logs

**Constraint:** RAG is explanation support only.

## 7. LLM Integration (OpenRouter)
### Model Policy
Use analytical reasoning models only.

### Recommended Routing
- Explanatory summarization: Kwaipilot KAT-Coder-Pro V1
- Short metric explanation: openrouter/ctl-large

### OpenRouter Design
- Single API key
- Model selected by request parameter
- Unified billing and model switching

### `llm_client.py` Responsibilities
- Inject system prompt
- Apply guardrails
- Control temperature (`0.1` to `0.2`)
- Enforce token limits
- Handle retries and errors

## 9. Guardrails (Non-Negotiable)
Enforce at both system prompt and application code:
- No buy/sell/hold advice
- No predictions
- No parameter suggestions
- Read-only access
- Metric-referenced explanations only

On violation requests: polite refusal and redirection to measurable metrics.

## 10. Caching and Cost Control
Use Redis to:
- Cache AI responses per report version
- Cache intermediate summaries
- Avoid repeated OpenRouter calls

Outcome: predictable latency and controlled inference cost.

## 17. Determinism, Contracts, and Validation Additions
These are mandatory implementation controls to make outputs reproducible, testable, and safe.

### 17.1 Determinism and Versioning Enforcement (Critical)
Add explicit analysis versioning and hash-driven cache keys.

**Required fields for version input:**
- `strategy_id`
- `strategy_version`
- `backtest_id` (if present)
- `paper_session_id` (if present)
- `report_updated_at` timestamps
- `engine_version`
- `prompt_version`
- `rag_index_version`
- `metric_schema_version`

**Required computed identifiers:**
- `context_hash = sha256(canonical_context_payload)`
- `analysis_version = "v{engine_version}:{prompt_version}:{metric_schema_version}"`

**Redis cache key contract:**
- `ai:analysis:{endpoint}:{model}:{analysis_version}:{context_hash}`

**Effect:**
- Any change to report data, prompt, schema, or engine invalidates stale outputs automatically.

### 17.2 Metric Canonicalization Contract (Explicit Schema)
ContextBuilder must normalize all inputs to one internal schema before LLM calls.

**Canonical metrics schema (minimum):**
```json
{
  "net_pnl": 0.0,
  "total_return_pct": 0.0,
  "cagr_pct": 0.0,
  "sharpe_ratio": 0.0,
  "calmar_ratio": 0.0,
  "max_drawdown_pct": 0.0,
  "drawdown_duration_days": 0,
  "volatility_annual_pct": 0.0,
  "expectancy": 0.0,
  "profit_factor": 0.0,
  "trade_count": 0,
  "win_rate_pct": 0.0,
  "avg_win_pct": 0.0,
  "avg_loss_pct": 0.0
}
```

**Unit rules:**
- Percent fields use percentage units (e.g., `12.5` means `12.5%`, not `0.125`).
- Ratio fields are unitless.
- Duration fields are integer days.

### 17.3 Cross-Report Divergence Logic (Must Be Explicit)
ContextBuilder must compute comparison features, not just summarize reports independently.

**Required comparison features:**
- `pnl_delta_pct = paper_total_return_pct - backtest_total_return_pct`
- `win_rate_drift_pct_pts = paper_win_rate_pct - backtest_win_rate_pct`
- `drawdown_expansion_pct_pts = paper_max_drawdown_pct - backtest_max_drawdown_pct`
- `trade_frequency_change = paper_trades_per_day / backtest_trades_per_day` (safe divide)

**Required qualitative classification:**
- Divergence tags: `aligned`, `moderate_drift`, `high_drift`
- Explicit evidence list referencing metric deltas used for each tag

### 17.4 Output Structure Validation (Contract, Not Trust-Based)
All AI endpoints must return a validated structure.

**Option A (preferred):** enforce JSON schema from LLM output.

**Minimum response contract:**
```json
{
  "summary": "string",
  "strengths": ["string"],
  "weaknesses": ["string"],
  "risk_structure": ["string"],
  "stability_assessment": "string",
  "caveats": ["string"],
  "evidence": [{"metric": "string", "value": "number", "source": "string"}],
  "confidence_level": "low|medium|high",
  "data_sufficiency_flags": ["string"],
  "analysis_version": "string",
  "context_hash": "string"
}
```

If validation fails, return a controlled fallback response with the same schema.

### 17.5 Confidence and Data Sufficiency Signaling (Mandatory)
Prevent false authority by explicitly rating data sufficiency before generation.

**Minimum gating checks:**
- `trade_count < 30` -> force `confidence_level = low`
- `backtest_duration_days < 30` -> force `confidence_level = low`
- `30 <= trade_count < 100` or `30 <= duration_days < 180` -> at most `medium`
- `trade_count >= 100` and `duration_days >= 180` -> eligible for `high`

**Required output fields:**
- `confidence_level: low | medium | high`
- `data_sufficiency_flags` (examples: `low_trade_count`, `short_test_window`, `missing_strategy_tests`)

The model must explicitly disclose low-confidence reasoning in summary and caveats.
