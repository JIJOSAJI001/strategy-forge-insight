## ✅ Frontend Deployment (Vercel)

### The 404 Fix
The `vercel.json` file has been configured to handle client-side routing properly. This ensures that when users reload pages like `/dashboard` or `/strategies`, they won't see a 404 error.

### Configuration Details

**File: `vercel.json`**
```json
{
  "buildCommand": "cd frontend && npm install && npm run build",
  "outputDirectory": "frontend/dist",
  "rewrites": [
    {
      "source": "/(.*)",
      "destination": "/index.html"
    }
  ],
  "headers": [
    {
      "source": "/assets/(.*)",
      "headers": [
        {
          "key": "Cache-Control",
          "value": "public, max-age=31536000, immutable"
        }
      ]
    }
  ]
}
```

### What This Does:
1. **Rewrites**: All routes (`/(.*)`) are redirected to `/index.html`, allowing React Router to handle routing
2. **Build Command**: Specifies how to build your frontend
3. **Output Directory**: Points to the Vite build output (`frontend/dist`)
4. **Headers**: Optimizes caching for static assets

### Deployment Steps:

1. **Connect to Vercel**
   ```bash
   # Install Vercel CLI (if not already installed)
   npm i -g vercel
   
   # Login to Vercel
   vercel login
   
   # Deploy
   vercel
   ```

2. **Or Deploy via Vercel Dashboard**
   - Go to [vercel.com](https://vercel.com)
   - Import your GitHub repository
   - Vercel will automatically detect the `vercel.json` configuration
   - Click "Deploy"

3. **Configure Environment Variables**
   Go to your Vercel project settings and add:
   - `VITE_API_URL` - Your Render backend URL (e.g., `https://strategy-forge-backend.onrender.com`)
   - Any other environment variables your frontend needs

## ✅ Backend Deployment (Render)

### Configuration Details

**File: `render.yaml`**
```yaml
services:
  - type: web
    name: strategy-forge-backend
    env: python
    region: oregon
    buildCommand: cd Backend && pip install -r requirements.txt
    startCommand: cd Backend && uvicorn main:app --host 0.0.0.0 --port $PORT
    envVars:
      - key: PYTHON_VERSION
        value: 3.11.0
      - key: PORT
        generateValue: true
```

### Deployment Steps:

1. **Connect to Render**
   - Go to [render.com](https://render.com)
   - Sign in with GitHub
   - Click "New +" → "Web Service"
   - Connect your repository

2. **Configure the Service**
   - **Name**: `strategy-forge-backend`
   - **Region**: Choose closest to your users
   - **Branch**: `sub_project` (or your main branch)
   - **Root Directory**: Leave empty (or set to `Backend` if needed)
   - **Environment**: `Python 3`
   - **Build Command**: `cd Backend && pip install -r requirements.txt`
   - **Start Command**: `cd Backend && uvicorn main:app --host 0.0.0.0 --port $PORT`

3. **Add Environment Variables**
   In Render Dashboard, add these environment variables:
   - `MONGODB_URI` - Your MongoDB connection string
   - `REDIS_URL` - Your Redis connection string
   - `SECRET_KEY` - Your application secret key
   - `FIREBASE_CREDENTIALS` - Firebase service account JSON (if needed)
   - `CORS_ORIGINS` - Your Vercel frontend URL
   - `PORT` - Will be auto-generated by Render
   - Any other backend config variables

4. **Deploy**
   - Click "Create Web Service"
   - Render will automatically build and deploy your backend

## 🔧 CORS Configuration

Make sure your backend CORS settings include your Vercel frontend URL:

**In `Backend/main.py`:**
```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=[
        "http://localhost:8080",  # Local development
        "https://your-app.vercel.app",  # Your Vercel deployment
        "https://your-custom-domain.com",  # Your custom domain (if any)
    ],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

## 📝 Important Notes

### For Vercel:
- The `vercel.json` file MUST be in the root directory of your repository
- Vite build output is in `frontend/dist` by default
- Environment variables starting with `VITE_` are exposed to the client

### For Render:
- Free tier may have cold starts (initial requests may be slow)
- Consider upgrading to paid tier for production
- Render automatically sets the `PORT` environment variable
- Your backend must listen on `0.0.0.0` (not `localhost`) for Render to work

### Security:
- Never commit sensitive data (API keys, credentials) to Git
- Always use environment variables for secrets
- Use `.env.example` files to document required variables

## 🐛 Troubleshooting

### Frontend 404 Issues:
- ✅ Verify `vercel.json` is in the root directory
- ✅ Check Vercel build logs for errors
- ✅ Ensure output directory is correct (`frontend/dist`)
- ✅ Clear browser cache and hard reload

### Backend Issues:
- Check Render logs for errors
- Verify all environment variables are set
- Test endpoints directly using Postman/curl
- Ensure MongoDB and Redis are accessible from Render

### CORS Errors:
- Add your Vercel URL to backend CORS origins
- Check browser console for specific CORS errors
- Verify credentials are being sent correctly
